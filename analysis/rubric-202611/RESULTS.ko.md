# 검증된 Vanda 결과 (2026년 11월 5일)

[English](RESULTS.md) · [中文](RESULTS.zh-CN.md)

여섯 작업이 `python3 scripts/reproduce_rubric.py --verify-only`를 통과했습니다. **일반 측정 275개와 독립 진단 75개**이며 소스 일치, 증거 해시, 실제 CUDA 실행, 256코어 사전 검증, 작업 스레드 배치, 작업량, 수치 일관성을 확인합니다. 봉인된 증거는 `../../benchmarks/rubric-202611/`에 있습니다.

## 방법과 해석 범위

FP64, seed=42, 측정 반복 20회, 준비 반복 2회 후 초기화, 설정별 재측정 5회를 사용합니다. 아래 시간은 중앙값이며 오차 막대는 관측 최솟값–최댓값으로 신뢰구간이 아닙니다. 강 확장/혼합/통신은 N=4,000,000,D=K=32입니다. 약 확장은 rank당 100,000개 표본을 유지하며 최대 N=25,600,000입니다. 노드당 실제 C=64개 물리 코어, 최대 4노드/256코어를 사용합니다. GPU 비교는 NVIDIA A40 1개(보고된 메모리 46,068 MiB)와 같은 작업의 CPU1/CPU8 기준입니다.

호스트는 Intel Xeon Platinum 8452Y이며 CPU 72개, 소켓 2개, 소켓당 36코어, 코어당 1스레드, NUMA 노드 2개를 노출합니다. PBS는 CPU 할당을 노드당 64 CPUs/444 GB, GPU 작업을 36 CPUs/240 GB/GPU 1개로 정규화했습니다. 예약 자원과 실제 사용 자원을 구별합니다. GCC 11.3.0, Open MPI 4.1.8, CUDA 12.4.131/sm_86, 드라이버 575.57.08을 사용했습니다.

루프와 내부 전체 시간을 따로 보고합니다. 전체 시간은 데이터 준비, 초기화, 장치 설정, 준비 반복, 최종 평가를 포함하고 MPI 초기화와 외부 프로세스 시작은 제외합니다. 진단을 일반 성능 표본에 섞지 않으며 MPI 시간에는 대기가 포함됩니다. 합성 데이터와 고정 반복의 성능 결과로 실제 데이터 군집 정확도나 수렴 속도를 주장하지 않습니다.

## 순차 문제 크기

D=K=32에서 N=100,000→4,000,000의 40배 증가는 0.748800→29.963383초, 즉 40.01배 시간을 보입니다. D=8→128은 시간 16.04배, K=8→128은 14.74배입니다. O(INKD)는 계산량을 설명하지만 형태별 정규화 상수는 일정하지 않습니다. 캐시나 벡터화의 특정 기여는 측정하지 않았습니다.

## 순수 MPI 강 확장

| 설정 | 루프 중앙값 (초) | 같은 작업 V0 대비 가속비 | 효율 |
|---|---:|---:|---:|
| V0 | 29.975499 | 1.00 | — |
| V1 / 64코어 | 0.766059 | 39.13 | 61.14% |
| V1 / 128코어 | 0.402175 | 74.53 | 58.23% |
| V1 / 256코어 | 0.229259 | 130.75 | 51.07% |

같은 작업의 V1/P=1(29.772404초)을 기준으로 하면 256코어 가속비는 129.86배, 효율은 50.73%입니다. P≤64는 노드 1개, 128은 2개, 256은 4개입니다. 단일 노드에서도 효율 저하가 있습니다. 대표 P=256 진단의 축약은 0.040181초로 해당 0.227751초 루프의 17.64%입니다. 순수 네트워크 시간이나 일반 표본의 평균 비중은 아닙니다.

## 순수 MPI 약 확장

P=1 중앙값은 0.763801초, P=256은 1.331356초입니다. 약 확장 효율 T1/TP는 **57.37%**, 처리량 가속비 P×T1/TP는 **146.87배**입니다. 고정 크기 순차 가속비와 다릅니다. P=256 진단의 축약 비중은 4.93%인 반면 로컬 누적은 P=1의 0.763034초에서 1.263653초로 증가합니다. 통신만으로 손실을 설명할 수 없으며 시스템/NUMA/자원 효과는 아직 분리하지 못했습니다.

## 통신

| P | Allreduce (초) | Reduce+Bcast (초) | 변화 |
|---|---:|---:|---:|
| 64 | 0.541884 | 0.541480 | -0.07% |
| 256 | 0.225697 | 0.224374 | -0.59% |

범위가 겹쳐 안정적인 우위를 입증하지 못합니다. Reduce+Bcast의 broadcast/control을 포함해야 하며 축약만 비교하면 필수 작업을 누락합니다. 이 작업 시간을 다른 강 확장 작업의 기준으로 대체하지 않습니다.

## 고정 256코어 MPI+OpenMP

같은 작업의 V1/256은 0.228162초입니다. V3 최소 중앙값은 64×4의 0.225800초로 **1.04% 감소**에 그치며 범위가 겹칩니다. V2/32×8은 0.694824초로 순수 MPI보다 **204.53% 느립니다**. 동일 배치 V3는 0.226163초로 V2보다 3.07배 빠릅니다.

32×8 대표 진단의 누적은 V2 0.639223초, V3 0.191290초입니다. V3 병합은 0.000208초, 해당 루프의 0.091%입니다. 전용 버퍼가 큰 누적 페널티를 줄이지만 시간 차이를 순수 atomic 대기로 해석하지 않습니다. V3/64×4 전체 시간은 0.407674초로 V1/256의 0.316061초보다 길어 작은 루프 이득이 전체 이득을 뜻하지 않습니다.
